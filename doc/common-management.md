# 공통 관리 — UI/상호작용 공통 규칙

[메인 지시서](../CLAUDE.md)의 보조 문서. 글자 크기 조절, 마우스 오버 학습 팝업의 표시 조건·동작·데이터 구조 등 이 기능 전반에 공통으로 적용되는 규칙을 정의한다.

---

## 1. 글자 크기 조절

텍스트 창에 표시되는 영어 글자의 크기를 사용자가 조절할 수 있도록 한다.

### 1.1 글자 크게 버튼

`+` 또는 `A+` 형태의 버튼을 제공한다.

버튼을 클릭하면 영어 텍스트의 글자 크기를 증가시킨다.

예: 16px → 18px → 20px → 22px 등의 방식으로 단계적으로 증가시킨다.

### 1.2 글자 작게 버튼

`-` 또는 `A-` 형태의 버튼을 제공한다.

버튼을 클릭하면 영어 텍스트의 글자 크기를 감소시킨다.

예: 22px → 20px → 18px → 16px

### 1.3 글자 크기 제한

글자가 지나치게 커지거나 작아지지 않도록 최소/최대 크기를 설정한다.

```text
최소 크기: 12px
기본 크기: 18px
최대 크기: 36px
증감 단위: 2px
```

실제 값은 기존 프로젝트의 UI 규칙에 맞게 조정할 수 있다.

---

## 2. 마우스 오버 학습 기능

영어 텍스트에 포함된 특정 단어 또는 표현 위에 마우스를 올리면 해당 단어/표현에 대한 학습 정보를 팝업으로 표시한다.

예:

```text
I was wondering if you could help me.
       ↑
     마우스 오버
```

마우스가 `wondering if`와 같이 등록된 표현 위에 올라가면 해당 표현에 대한 팝업을 표시한다.

---

## 3. 표현 단위 처리

단순히 하나의 단어만 인식하는 것이 아니라 **여러 단어로 구성된 영어 표현**도 인식할 수 있어야 한다.

예:

```text
look forward to
be supposed to
would like to
I was wondering if
as far as I know
```

따라서 마우스 오버 대상은 다음과 같이 구분할 수 있어야 한다.

### 단일 단어

```text
wonder
help
problem
```

### 복수 단어 표현

```text
wondering if
look forward to
be supposed to
as far as I know
```

등록된 표현이 존재하는 경우 가능한 한 **하나의 표현 단위**로 처리한다.

---

## 4. 팝업 표시 조건

팝업에 어떤 정보를 표시할 것인지는 사용자가 선택할 수 있어야 한다.

선택 가능한 조건은 다음 세 가지다.

```text
□ 해석
□ 영작
□ 표현
```

또는 UI 특성에 따라 버튼/탭/체크박스 등의 형태로 구현할 수 있다.

---

## 5. 해석

사용자가 `해석`을 선택한 경우 마우스 오버한 영어 단어 또는 표현에 대한 한국어 해석을 팝업으로 표시한다.

예:

```text
[해석]

look forward to

~을 기대하다
~을 고대하다
```

문장 전체의 해석이 필요한 경우에는 해당 표현이 포함된 문장을 기준으로 해석 정보를 제공할 수 있다.

---

## 6. 영작

사용자가 `영작`을 선택한 경우 해당 표현을 활용한 영어 작문 관련 정보를 팝업으로 표시한다.

예:

```text
[영작]

"~을 기대하다"를 영어로 표현하면:

look forward to

예문:
I look forward to meeting you.
```

영작 정보는 사용자가 영어 표현을 실제 문장에 활용할 수 있도록 구성한다.

가능하면 다음 정보를 포함한다.

* 한국어 의미
* 대응하는 영어 표현
* 영어 예문
* 필요한 경우 문장 구조 설명

---

## 7. 표현

사용자가 `표현`을 선택한 경우 해당 영어 단어 또는 표현의 영어 학습 정보를 표시한다.

예:

```text
[표현]

look forward to

의미:
~을 기대하다 / ~을 고대하다

사용법:
look forward to + 명사
look forward to + 동명사(-ing)

Example:
I look forward to seeing you.
```

표현 정보에는 다음과 같은 항목을 활용할 수 있다.

* 표현의 의미
* 품사
* 사용 방법
* 문장 구조
* 비슷한 표현
* 예문
* 주의사항

단, 실제 데이터에 존재하는 정보만 표시한다.

---

## 8. 복수 조건 선택

해석 / 영작 / 표현은 하나만 선택할 필요가 없다.

여러 항목을 동시에 선택할 수 있어야 한다.

예:

```text
☑ 해석
☑ 영작
☐ 표현
```

이 경우 팝업에는 해석과 영작 정보만 표시한다.

또 다른 예:

```text
☑ 해석
☑ 영작
☑ 표현
```

이 경우 세 가지 정보를 모두 표시한다.

---

## 9. 선택 조건이 없는 경우

사용자가 아무 조건도 선택하지 않은 상태에서는 팝업을 표시하지 않는다.

예:

```text
☐ 해석
☐ 영작
☐ 표현
```

이 상태에서 영어 단어에 마우스를 올려도 학습 팝업을 표시하지 않는다.

---

## 10. 팝업 동작

### 10.1 표시

사용자가 학습 대상 단어 또는 표현 위에 마우스를 올리면 팝업을 표시한다.

팝업에는 현재 마우스가 위치한 단어/표현을 기준으로 정보를 표시한다.

예:

```text
┌──────────────────────────┐
│ look forward to           │
├──────────────────────────┤
│ 해석                      │
│ ~을 기대하다              │
│                           │
│ 영작                      │
│ I look forward to seeing  │
│ you.                      │
└──────────────────────────┘
```

### 10.2 위치

팝업은 마우스 위치 또는 해당 단어 주변에 표시한다.

팝업이 화면 밖으로 나가는 경우에는 자동으로 위치를 조정한다.

### 10.3 마우스 이동

마우스가 다른 학습 대상 표현으로 이동하면 기존 팝업 내용을 새로운 표현의 정보로 변경한다.

예:

```text
look forward to
       ↓
be supposed to
```

마우스가 이동하면 팝업도 해당 표현에 맞게 변경한다.

### 10.4 마우스가 텍스트 영역을 벗어난 경우

마우스가 학습 대상 텍스트 영역을 벗어나면 팝업을 닫는다.

단, 사용자가 팝업 내부의 내용을 확인하거나 선택할 수 있도록 필요한 경우 약간의 지연 시간을 둘 수 있다.

예:

```text
마우스 오버
   ↓
약 200~300ms
   ↓
팝업 표시
```

실제 지연 시간은 UX 테스트를 통해 조정한다. (본 프로젝트에서 확정한 값은 §26.3 참고)

## 11. UI 구성

전체 UI는 다음과 같은 구조를 기본으로 한다.

```text
┌──────────────────────────────────────────────┐
│ 영어 학습                                    │
├──────────────────────────────────────────────┤
│                                              │
│  [A-] [A+]     [해석] [영작] [표현]          │
│                                              │
├──────────────────────────────────────────────┤
│                                              │
│  I was wondering if you could help me       │
│  with this problem.                          │
│                                              │
│  I look forward to seeing you again.        │
│                                              │
│                         ┌─────────────────┐  │
│                         │ look forward to │  │
│                         │                 │  │
│                         │ 해석            │  │
│                         │ ~을 기대하다    │  │
│                         └─────────────────┘  │
│                                              │
└──────────────────────────────────────────────┘
```

## 12. 데이터 구조

각 영어 단어 또는 표현은 학습 정보를 가지고 있어야 한다.

개념적으로 다음과 같은 구조를 사용한다.

```text
LearningExpression
├── text
├── interpretation
├── writing
└── expression
```

예:

```json
{
   "text": "look forward to",

   "interpretation": {
       "ko": "~을 기대하다, ~을 고대하다"
   },

   "writing": {
       "description": "한국어 '~을 기대하다'를 영어로 표현",
       "example": "I look forward to seeing you."
   },

   "expression": {
       "meaning": "~을 기대하다",
       "usage": "look forward to + noun / gerund",
       "example": "I look forward to meeting you."
   }
}
```

실제 프로젝트에서는 기존 데이터 구조가 있다면 기존 구조를 우선 사용한다. (본 프로젝트의 실제 구현은 §26.2, [doc/expression-management.md](expression-management.md) 참고 — `interpretation`/`writing`/`expression`이 각각 별도 파일로 저장되고, 화면에 표시되기 직전에 `text` 기준으로 병합된다.)

---

## 13. 텍스트와 학습 데이터 연결

화면에 표시되는 영어 텍스트와 학습 데이터가 연결되어 있어야 한다.

예를 들어 텍스트가 다음과 같은 경우:

```text
I look forward to seeing you.
```

학습 데이터에 다음 표현이 등록되어 있다면:

```text
look forward to
```

텍스트에서 해당 영역을 마우스 오버했을 때 `look forward to`에 대한 학습 정보를 찾아 팝업에 표시한다.

---

## 14. 단어 매칭 우선순위

여러 표현이 중복되는 경우에는 더 긴 표현을 우선적으로 매칭한다.

예:

```text
look
look forward
look forward to
```

문장에 다음과 같이 존재한다면:

```text
I look forward to seeing you.
```

`look`이 아니라 가장 긴 일치 표현인 `look forward to`를 학습 대상으로 처리한다.

즉, 기본적인 우선순위는 다음과 같다.

```text
긴 표현
  ↓
짧은 표현
  ↓
단일 단어
```

---

## 15. 학습 데이터가 없는 경우

마우스가 영어 텍스트의 일반적인 단어 위에 올라갔더라도 해당 단어/표현에 대한 학습 데이터가 없다면 팝업을 표시하지 않는다.

예:

```text
문장:
I went to the office yesterday.

등록된 학습 데이터:
went to
```

`went to`에는 팝업을 표시할 수 있지만, 학습 데이터가 없는 단어에는 팝업을 표시하지 않는다.

---

## 16. 선택 상태 관리

해석 / 영작 / 표현의 선택 상태는 현재 텍스트 창에 적용되는 상태로 관리한다.

예:

```text
해석 = true
영작 = false
표현 = true
```

이 상태에서는 팝업에 다음만 표시한다.

```text
해석
표현
```

사용자가 `영작`을 추가로 선택하면 즉시 다음 상태가 된다.

```text
해석 = true
영작 = true
표현 = true
```

이후 표시되는 팝업에는 세 가지 정보가 모두 표시된다.

---

## 17. 버튼 상태 표시

선택된 조건과 선택되지 않은 조건을 UI에서 명확하게 구분한다.

예:

```text
[해석]   [영작]   [표현]
  ON       OFF       ON
```

선택된 버튼은 사용자가 현재 활성화 상태임을 쉽게 알 수 있어야 한다.

---

## 18. 글자 크기와 팝업의 관계

영어 텍스트의 글자 크기를 변경해도 마우스 오버 영역과 팝업 기능이 정상적으로 동작해야 한다.

```text
기본 크기 → A+ → 큰 글자 → 마우스 오버 → 정상적으로 표현 인식 → 팝업 표시
```

글자 크기를 변경했다고 해서 단어의 인식 범위나 팝업 기능이 깨지면 안 된다.

---

## 19. 성능 요구사항

영어 텍스트가 길어질 수 있으므로 모든 마우스 이동마다 전체 텍스트를 다시 분석하는 방식은 가능한 한 피한다.

권장 방식:

```text
텍스트 로딩
   ↓
학습 대상 표현 분석
   ↓
표현별 영역 생성
   ↓
마우스 오버 이벤트 연결
```

또는 프로젝트의 UI 프레임워크에 맞는 효율적인 방식으로 구현한다.

특히 긴 영어 문서에서도 마우스 이동 시 지연이 발생하지 않도록 한다.

## 20. 예외 처리

다음 상황에서도 오류가 발생하지 않아야 한다.

### 학습 데이터가 없는 경우

팝업을 표시하지 않는다.

### 해석 데이터가 없는 경우

해석을 선택했더라도 해당 데이터가 없다면 해당 영역을 표시하지 않는다.

### 영작 데이터가 없는 경우

영작을 선택했더라도 해당 데이터가 없다면 해당 영역을 표시하지 않는다.

### 표현 데이터가 없는 경우

표현을 선택했더라도 해당 데이터가 없다면 해당 영역을 표시하지 않는다.

### 모든 데이터가 없는 경우

팝업을 표시하지 않는다.

## 22. 구현 시 중요 사항

다음 사항을 반드시 준수한다.

1. 영어 텍스트는 일반적인 단순 Label/Text 형태가 아니라 **단어 또는 표현 단위로 마우스 오버를 감지할 수 있는 구조**로 구현한다.
2. 단일 단어뿐만 아니라 여러 단어로 구성된 표현을 지원한다.
3. 여러 표현이 겹칠 경우 가장 긴 표현을 우선한다.
4. 해석 / 영작 / 표현은 독립적으로 선택할 수 있어야 한다.
5. 선택된 정보만 팝업에 표시한다.
6. 선택된 정보에 실제 데이터가 없는 경우 해당 항목은 표시하지 않는다.
7. 표시할 정보가 하나도 없으면 팝업을 표시하지 않는다.
8. 글자 크기를 변경해도 마우스 오버 기능이 정상적으로 유지되어야 한다.
9. 마우스가 다른 단어/표현으로 이동하면 팝업의 내용도 해당 표현에 맞게 변경되어야 한다.
10. 텍스트 영역을 벗어나면 팝업을 닫는다.
11. 팝업이 화면 영역 밖으로 나가지 않도록 위치를 자동 조정한다.
12. 긴 텍스트에서도 불필요하게 전체 텍스트를 반복 분석하지 않도록 구현한다.

## 23. 완료 기준

다음 테스트를 모두 통과하면 기능 구현이 완료된 것으로 판단한다.

* **Test 1 — 영어 텍스트 표시**: 영어 문장이 정상적으로 텍스트 창에 표시된다.
* **Test 2 — 글자 크기 증가**: `A+` 버튼을 클릭하면 영어 텍스트가 단계적으로 커진다.
* **Test 3 — 글자 크기 감소**: `A-` 버튼을 클릭하면 영어 텍스트가 단계적으로 작아진다.
* **Test 4 — 해석 팝업**: `해석`을 선택하고 학습 표현 위에 마우스를 올리면 해석 정보가 표시된다.
* **Test 5 — 영작 팝업**: `영작`을 선택하고 학습 표현 위에 마우스를 올리면 영작 정보가 표시된다.
* **Test 6 — 표현 팝업**: `표현`을 선택하고 학습 표현 위에 마우스를 올리면 표현 정보가 표시된다.
* **Test 7 — 복수 선택**: `해석 + 영작 + 표현`을 동시에 선택하면 세 가지 정보가 하나의 팝업에 표시된다.
* **Test 8 — 선택 해제**: 특정 조건을 해제하면 이후 팝업에서 해당 정보가 표시되지 않는다.
* **Test 9 — 표현 우선순위**: `look`, `look forward`, `look forward to`가 모두 등록되어 있는 경우 `look forward to`를 하나의 표현으로 인식한다.
* **Test 10 — 데이터 없음**: 학습 데이터가 없는 단어에 마우스를 올렸을 때 불필요한 팝업이 표시되지 않는다.
* **Test 11 — 팝업 위치**: 화면 가장자리의 단어에 마우스를 올려도 팝업이 화면 밖으로 잘리지 않는다.
* **Test 12 — 글자 크기 변경 후**: 글자 크기를 여러 번 변경한 후에도 단어/표현 마우스 오버 기능이 정상적으로 동작한다.

## 24. 최종 사용자 동작 흐름

전체 기능의 사용자 흐름은 다음과 같다.

```text
영어 텍스트 표시
      ↓
사용자가 글자 크기 선택
      ↓
A- / A+ 버튼으로 크기 조절
      ↓
해석 / 영작 / 표현 선택
      ↓
영어 텍스트에서 학습하고 싶은 단어 또는 표현 위에 마우스 이동
      ↓
해당 단어/표현 확인
      ↓
선택된 조건의 학습 데이터 검색
      ↓
팝업 표시
      ↓
다른 표현으로 마우스 이동
      ↓
새로운 표현의 학습 정보로 팝업 갱신
      ↓
텍스트 영역을 벗어나면 팝업 종료
```

## 25. 구현 원칙

이번 기능의 핵심은 단순한 영어 텍스트 표시가 아니라 **영어 텍스트를 인터랙티브한 학습 콘텐츠로 만드는 것**이다.

따라서 UI 구현 시 다음 세 가지 기능이 서로 독립적으로 동작하면서도 자연스럽게 연결되도록 설계한다.

```text
┌──────────────────────────────┐
│        영어 텍스트            │
│                              │
│  [단어] [표현] [문장]          │
│      ↑                       │
│    Mouse Over                │
└──────────────┬───────────────┘
               ↓
        학습 데이터 검색
               ↓
     ┌─────────┴─────────┐
     │                   │
   해석                 영작
     │                   │
     └─────────┬─────────┘
               ↓
             표현
               ↓
          학습 팝업 표시
```

구현 시 기존 프로젝트의 구조와 스타일을 우선적으로 따르되, 기존 구조를 불필요하게 변경하지 않는다. 새로운 기능은 가능한 한 기존 컴포넌트와 데이터 구조를 재사용하여 추가한다.

## 26. 구현 결정 사항 (확정)

지시서 작성 시점에는 저장소에 기존 프로젝트가 없어 아래 항목들이 모호했다. 다음과 같이 확정했다.

### 26.1 기술 스택

**WPF (.NET) 데스크톱 앱**으로 구현한다.

* 영어 텍스트 표시 및 표현 단위 마우스 오버 감지는 `TextBlock`/`Run` 조합 또는 `InlineUIContainer` 기반 커스텀 컨트롤로 구현한다.
* 학습 팝업은 `Popup` 또는 `Adorner`를 사용해 구현한다.

### 26.2 학습 데이터 출처

**로컬 JSON 파일**을 데이터 소스로 사용한다. 외부 API/DB 연동은 하지 않는다.

해석/영작/표현은 각각 별도의 JSON 파일(`interpretations.json`/`writings.json`/`expressions.json`, `%LOCALAPPDATA%\EnglishTraining\`)로 관리하며, 각 파일은 전용 관리 창(해석 관리/영작 관리/표현 관리)에서 CRUD할 수 있다. 읽기 창은 세 파일을 `text` 기준으로 병합해 §12의 `LearningExpression` 형태로 만든 뒤 매칭에 사용한다. 자세한 내용은 [doc/expression-management.md](expression-management.md) 참고.

### 26.3 팝업 타이밍 (§10.1, §10.4 명확화)

* 마우스 오버 시 **표시(show)에만** 200~300ms 지연을 적용한다.
* 마우스가 학습 대상 영역을 벗어나면 **즉시** 팝업을 닫는다 (닫힘 지연 없음).

### 26.4 단어/표현 매칭 규칙 (§14 명확화)

* 매칭 전 텍스트를 **정규화**한다: 소문자 변환 + 구두점 제거 후 비교한다.
  * 예: `Look forward to,` → `look forward to` 로 정규화되어 매칭 대상이 된다.
* **어형 변화(활용형)는 자동 인식하지 않는다.** `look forward to`와 `looked forward to`는 별개의 문자열이므로, 활용형까지 인식하려면 학습 데이터에 별도 표현으로 각각 등록해야 한다.
* 정규화 후에도 최장 일치 우선 원칙(§14)은 그대로 적용한다.
