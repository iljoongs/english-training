# 단어/영작 관리 — 학습 데이터 관리 창

[메인 지시서](../CLAUDE.md)의 보조 문서. 읽기 창의 학습 팝업에 쓰이는 단어(해석)/영작 데이터를 각각 관리하는 두 창("단어 관리", "영작 관리")의 구조를 다룬다. 화면에 표시할 예문(주제) 자체는 [문장 관리](sentence-management.md)를 참고하고, 팝업에 데이터가 어떻게 조합되어 보이는지는 [공통 관리](common-management.md) §5~6, §12를 참고한다.

(한때 세 번째 관리 창 "표현 관리"도 있었으나 제거했다 — [공통 관리](common-management.md) §26.6. "해석 관리"는 이후 "단어 관리"로 이름이 바뀌고 `표현` 필드가 추가됐다 — §26.7.)

---

## 1. 개요

단어/영작 데이터는 예전에는 `expressions.json` 한 파일에 표현 데이터까지 합쳐져 있었지만, 지금은 각각 독립된 파일로 분리되어 있고 전용 관리 창을 통해 추가·수정·삭제할 수 있다.

| 관리 창 | 파일 | 필드 |
|---|---|---|
| 단어 관리 | `%LOCALAPPDATA%\EnglishTraining\interpretations.json` | 단어/숙어(`Text`), 품사(`PartOfSpeech`), 해석(`Ko`), 표현(`Expression`) |
| 영작 관리 | `%LOCALAPPDATA%\EnglishTraining\writings.json` | 표현(`Text`), 설명(`Description`), 예문(`Example`) |

두 창 모두 읽기 창(메인 윈도우)의 `Menu` → `Words`/`Writing` → `Setting`에서 연다([공통 관리](common-management.md) §26.11).

```text
읽기 창
   ↓
"Menu" 메뉴 클릭
   ↓
"Words" 또는 "Writing" 항목 클릭
   ↓
"Setting" 클릭
   ↓
해당 창에서 추가·수정·삭제
   ↓
창을 닫으면 읽기 창이 최신 데이터로 갱신됨(마우스오버 팝업에 즉시 반영)
```

관리 창을 열지 않고도, 읽기 창의 `Menu > Words`/`Menu > Writing`의 `Import`/`Export`로 각 저장소 전체를 `.md` 파일 하나로 바로 병합/내보내기할 수 있다(§26.11 — 아래 §5의 가져오기/내보내기와 파서는 같지만, 범위가 "선택 항목 1개"가 아니라 "전체 목록"이라는 점이 다르다).

## 2. 화면 구성 (두 창 공통)

```text
┌──────────────────────────────────────────────┐
│ 파일   단어(또는 영작)                         │
├──────────────────────────────────────────────┤
│ [신규] [가져오기] [삭제]                       │
├───────────────┬──────────────────────────────┤
│ look           │ 단어/숙어                     │
│ look forward   │ look forward to               │
│ look forward to│                                │
│ wondering if   │ 품사                          │
│                │ phrase                        │
│ [오름차순][내림│                                │
│  차순]        │ 해석                          │
│                │ ~을 기대하다, ~을 고대하다    │
│                │                                │
│                │ 표현                          │
│                │ look forward to + 동명사(-ing)│
├───────────────┴──────────────────────────────┤
│ C:\Users\...\interpretations.json (759 B)     │
└──────────────────────────────────────────────┘
```

* 최상단 메뉴: `파일`(열기/저장/다른 이름으로 저장), `<단어|영작>`(신규/가져오기/내보내기/삭제) — [문장 관리](sentence-management.md) §4와 동일한 구조.
* 좌측 목록: 등록된 표현(`Text`) 목록. 다중 선택 가능(삭제용). **기본적으로 `Text` 오름차순(가나다/알파벳순, 대소문자 무시)으로 정렬**되며, 목록 아래 `오름차순`/`내림차순` 버튼으로 다시 정렬할 수 있다. 정렬은 화면 표시 순서만 바꾸고 파일 저장 순서에는 영향을 주지 않는다.
* 우측: 선택된 항목의 필드를 편집하는 영역. 창마다 필드 구성이 다르다(위 §1 표 참고). 단어 관리는 단어/숙어(`Text`) · 품사(`PartOfSpeech`) · 해석(`Ko`) · 표현(`Expression`, 이 단어/숙어를 활용한 유용한 표현을 자유 텍스트로 적어두는 용도) 4개 필드를 편집한다.
* 하단: 현재 저장 파일의 `경로 (크기)` 상태 표시줄.

---

## 3. 신규 / 삭제

* **신규**: 표현(`Text`)을 입력받아 나머지 필드가 빈 항목을 추가하고 선택 상태로 만든다. 이후 우측에서 필드를 채운다.
* **삭제**: 좌측 목록에서 선택(다중 선택 가능)한 항목을 확인 후 삭제한다.

---

## 4. 파일 열기 / 저장 / 다른 이름으로 저장

문장 관리 §4.1과 동일하게 동작한다 — `열기`는 다른 JSON 파일로 전체 목록을 교체하고, `저장`은 현재 파일에, `다른 이름으로 저장`은 새 파일에 기록하며 이후 저장 대상도 그 파일로 바뀐다.

---

## 5. 가져오기 / 내보내기

문장 관리의 `.md` 가져오기/내보내기([sentence-management.md](sentence-management.md) §6)와 같은 방식으로, 항목 하나를 텍스트 파일로 주고받을 수 있다.

* **가져오기**: `.md` 파일을 선택하면 그 내용을 새 항목으로 추가한다. **단어 관리 창**은 `.md` 파일을 창 위로 드래그 앤 드롭해도 동일하게 동작한다(창 어디에 놓아도 인식되며, `.md` 확장자가 아닌 파일은 무시한다) — 영작 관리 창은 아직 드래그 앤 드롭을 지원하지 않는다.
  * **단어 관리의 가져오기는 두 형식을 자동으로 판별한다**(`InterpretationMarkdownParser.ParseAny`): 먼저 §29.1의 압축 형식(`단어(품사) (해석) (표현)` 단어 줄, `**문장**`+번역 줄)으로 시도해보고, 한 줄도 안 걸리면 아래의 `### 단어`/라벨 형식으로 파싱한다. `data/today.md`처럼 압축 형식으로만 쓰인 파일을 이 창의 가져오기로 열어도 단어들이 제대로 들어온다 — 예전에는 이 경우 라벨/헤딩이 없어 파일 전체가 제목만 있는 빈 항목 하나로 뭉개졌었다.
* **내보내기**: 좌측에서 선택된 항목 하나를 `.md` 파일로 저장한다. 선택된 항목이 없으면 안내 메시지를 표시한다.

### md 파일 형식 — 단일 항목

첫 줄의 `# 표현`이 `Text`가 되고, 그 아래 `라벨: 값` 형태의 줄들이 각 필드가 된다. 라벨 뒤의 내용은 다음 라벨이 나오기 전까지 여러 줄을 포함할 수 있다. 창마다 사용하는 라벨은 다음과 같다.

| 관리 창 | 라벨 |
|---|---|
| 단어 관리 | `품사:`, `해석:`, `표현:` |
| 영작 관리 | `설명:`, `예문:` |

샘플 파일: [doc/sample-interpretation.md](sample-interpretation.md), [doc/sample-writing.md](sample-writing.md)

```markdown
# would like to

품사: phrase
해석: ~하고 싶다
표현: would like to + 동사원형
```

```markdown
# would like to

설명: 정중하게 원하는 것을 표현할 때 사용
예문: I would like to know more about this.
```

두 파일 모두 같은 표현(`would like to`)을 예시로 쓴다 — 두 관리 창에 각각 가져오면 단어/영작 데이터가 `would like to` 기준으로 자동 병합되어(아래 §6) 읽기 창에서 하나의 학습 팝업으로 합쳐진다.

### md 파일 형식 — 여러 항목(하루치 단어장)

문장 관리의 다중 주제 파일([sentence-management.md](sentence-management.md) §6 "md 파일 형식 — 여러 주제")과 같은 방식으로, `### 표현`이 하나 이상 있으면 각 구간을 **별도 항목으로 각각** 추가한다(최상단 `# 날짜 ...` 제목은 항목명으로 쓰이지 않는다).

* `### 표현` → 항목의 `Text`.
* 그 구간의 본문 → 값. **라벨 없이 본문만 있으면 해당 창의 주 필드**(단어 관리는 `Ko`, 영작 관리는 `Example`)로 그대로 들어간다. 단어 관리에서 `품사`/`표현` 필드까지 함께 채우려면 `품사:`/`해석:`/`표현:` 라벨(또는 `#### 품사`/`#### 해석`/`#### 표현` 소제목)을 명시해야 한다(`라벨:` 콜론 스타일도 함께 지원).
* 실제 예시(직접 만든 파일): `data/2026-08-22-word.md`(단어), `data/2026-08-22-writings.md`(영작).

단어 관리(라벨 없음, 본문이 곧 해석):

```markdown
# 2026-08-22 단어/숙어

### deadline
마감일, 기한

### protection
보호
```

영작 관리(라벨 없음, 본문이 곧 예문):

```markdown
# 2026-08-22 영작

### deadline
Harry missed a deadline to tell the palace of his plans.
```

## 6. 읽기 창과의 데이터 병합

읽기 창은 시작할 때, 그리고 두 관리 창 중 하나가 닫힐 때마다 두 파일의 내용을 **정규화된 `Text` 기준으로 병합**해 학습 표현 목록(`LearningExpression`, [공통 관리](common-management.md) §12)을 다시 만든다.

* 같은 표현이 두 파일 중 한 곳에만 있어도 등록된 표현으로 인식되며, 팝업에는 실제로 데이터가 있는 항목만 표시된다([공통 관리](common-management.md) §20 예외 처리).
* 예를 들어 `look`이 `interpretations.json`에만 있으면, `look`에 마우스를 올렸을 때 단어 정보(품사/해석/표현)만 뜨고 영작 섹션은 표시되지 않는다.
* 학습 팝업에서 단어 정보는 `품사, 해석` 한 줄(품사가 없으면 해석만) 다음 구분선, 그 아래 `표현` 순서로 표시된다([공통 관리](common-management.md) §26.8). 단어 관리의 `표현` 필드가 비어 있으면 구분선과 표현 줄 자체가 표시되지 않는다.
* 표현 매칭의 정규화·최장 일치 규칙([공통 관리](common-management.md) §26.4)은 병합 후에도 그대로 적용된다 — 두 파일 중 어디에 있든 `Text`가 같으면(정규화 기준) 같은 표현으로 취급된다.
